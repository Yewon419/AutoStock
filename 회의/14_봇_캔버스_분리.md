# 봇 단위 strategy·캔버스 분리

> 작성일: 2026-05-15
> 목적: AI 팔레트(LLM 전략 생성·튜닝)와 캔버스 UI를 **봇 1:1 모델**로 재구성. 봇 페이지 안에서 그 봇 전용으로 strategy 생성·수정·튜닝 가능.
> 동기: 같은 strategy를 여러 봇이 공유하는 케이스가 사실상 없고, 운영 중 LLM 어시스턴트와의 대화 흐름(이 세션에서 한 진단→제안→적용)을 프론트에 그대로 옮기기 위함.

---

## 새 데이터 모델

```
bot (1) ── (1) strategy ── (1) canvas (노드 그래프)
                                  └─ AI 대화 + 노드 편집 둘 다 여기서
```

- **strategies.bot_id**: NOT NULL, UNIQUE, FK → trading_bots.id, ON DELETE CASCADE
- **trading_bots.strategy_id**: 기존 유지 (역참조용, ON DELETE SET NULL)
- 봇 삭제 시 strategy·캔버스·history·suggestions 모두 cascade 삭제

## Phase 1 계획 (대기)

### 백엔드 변경

- `POST /trading/bots` 변경: 봇 생성 시 빈 strategy 동반 생성 (단일 트랜잭션)
- `/ai/generate-strategy` 폐기 → `POST /trading/bots/{bot_id}/canvas/ai-generate` (그 봇 전용)
- `/ai/canvas-assistant` 변경: canvas_id 자리에 bot_id 받음 (대화형 어시스턴트)
- `POST /trading/bots/{bot_id}/strategy/apply-diff` — 1클릭 적용 + history 기록
- `POST /trading/bots/{bot_id}/strategy/undo` — history 마지막 복원
- `GET /trading/bots/{bot_id}/strategy/history` — 변경 이력 조회
- `GET /trading/bots/{bot_id}/suggestions` — 제안함 조회
- 08:30 자동 task 재설계 (`llm_strategy.generate_strategy` → `llm_strategy.propose_tuning_for_running_bots`):
  - RUNNING 봇 순회 → 봇별 거래 통계 진단 → LLM 변형판 제안 → `tuning_suggestions` 드롭

### 안전장치

- 봇이 RUNNING 중에 strategy 수정 = 다음 사이클부터 새 conditions 적용 (`bot_engine.run_all_bots`가 매 사이클 DB 재조회 — 검증됨)
- risk_params 변경 시 4종목 동시 SL 손실이 MDD 가드 초과하는지 사전 검사
- 모든 변경은 `strategy_history`에 before/after 기록 → undo 가능

## Phase 2~4 (대기)

### Phase 2 — 프론트 봇 페이지 탭화

- `BotDetailView.vue` 탭 구조 `[캔버스] [상세정보]`

  - 노드 편집 영역 (기존 캔버스 UI)

- 배지 클릭 → 해당 봇 캔버스 탭에서 제안 확인·1클릭 적용

### Phase 4 — 라우팅 정리

- 네비게이션 메뉴 정리
