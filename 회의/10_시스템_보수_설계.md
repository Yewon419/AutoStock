### P1. backtest_engine — volume_ratio 등 누락 지표 추가
**파일**: `backend/services/backtest_engine.py`
**문제**: `SUPPORTED_INDICATORS`에 `volume_ratio`, `vwap`, `price_vs_vwap`, `opening_gap`, `ma5_minus_ma20` 없음
→ LLM이 이 지표를 조건에 넣어도 백테스트에서 전부 `False` 처리됨

**수정 내용**:
```python
SUPPORTED_INDICATORS = {
    # 기존
    'rsi', 'macd', 'macd_signal', 'macd_histogram',
    'stoch_k', 'stoch_d',
    'bollinger_upper', 'bollinger_middle', 'bollinger_lower',
    'ma_20', 'ma_50', 'ma_200',
    'atr', 'adx', 'obv',
    # 추가
    'volume_ratio',     # StockPrice.volume / 20일 평균 (동적 계산)
    'ma_5', 'ma_10',    # TechnicalIndicator에 있는 경우
    'vwap',             # intraday 지표 (일봉에선 skip)
    'price_vs_vwap',
    'ma5_minus_ma20',
    'opening_gap',
}
```

`volume_ratio`는 TechnicalIndicator에 컬럼이 없으므로 **StockPrice에서 동적 계산** 필요:
- 백테스트 시 ticker별 20일 평균 거래량 사전 계산 → `ind_row` 대신 별도 맵으로 전달
- `_evaluate_condition`에 `vol_context` 파라미터 추가

**완료 기준**: LLM이 `volume_ratio above 2.0` 조건을 생성했을 때 백테스트에서 실제로 동작함

### P2. backtest_engine — 기본 손절/익절 적용
**파일**: `backend/services/backtest_engine.py`
**문제**: `stop_loss_pct`, `take_profit_pct`를 호출자가 안 넘기면 **무한 보유** → 전략 과대평가

**수정 내용**:
```python
def run_backtest(
    ...
    stop_loss_pct: Optional[float] = 7.0,    # None → 7.0으로 기본값 변경
    take_profit_pct: Optional[float] = 15.0, # None → 15.0으로 기본값 변경
    max_hold_days: int = 20,                 # 신규: 최대 보유 기간 (거래일 기준)
    next_day_fill: bool = True,              # 신규: 다음날 시가 체결 옵션
):
```

`next_day_fill=True` 시 체결 로직:
- 매수 신호 발생일 → **다음날 시가**(`open_price`)로 체결
- StockPrice에 `open_price` 컬럼 있는지 확인 필요

`max_hold_days`: 지정 거래일 초과 보유 시 강제 청산 (기간 종료와 별개)

**완료 기준**: 동일 전략 백테스트 시 손절 적용본이 미적용본보다 MDD 낮고 거래수 증가

### P3. LLM 전략 생성 — 백테스트 게이팅
**파일**: `backend/tasks/llm_strategy.py`
**문제**: 백테스트 결과가 나빠도 전략이 그대로 DB 저장됨

**수정 내용**: `_save_strategy` 호출 전 게이팅 로직 추가
```python
def _gate_strategy(backtest: dict) -> tuple[bool, str]:
    """백테스트 결과 기반 전략 품질 게이팅"""
    if not backtest:
        return True, ""  # 백테스트 실패 시 통과 (데이터 없음)

    trades = backtest.get("num_trades", 0)
    ret = backtest.get("total_return_pct", 0)
    win_rate = backtest.get("win_rate", 0)

    if trades < 3:
        return False, f"거래 횟수 부족 ({trades}회) — 신호 조건이 너무 엄격함"
    if ret < -15:
        return False, f"수익률 미달 ({ret:.1f}%) — 명백한 손실 전략"
    if trades > 3 and win_rate < 25:
        return False, f"승률 미달 ({win_rate:.1f}%) — 방향성 없음"

    return True, ""
```

게이팅 실패 시 전략 저장 건너뛰고 `status: "gated"` 반환.
AI 신뢰도(`ai_confidence`)를 Claude 자기평가 대신 **샤프비율 기반 점수**로 교체:
```python
sharpe = backtest.get("sharpe_ratio", 0)
confidence = min(100, max(0, int(50 + sharpe * 20)))  # sharpe 1.0 → 70점
```

**완료 기준**: 백테스트 수익률 -15% 미만 전략이 DB에 저장되지 않음

### P4. 봇 엔진 — 일봉 봇 1일 1회 체크
**파일**: `backend/tasks/bot_engine.py`
**문제**: 일봉 지표는 전날 종가 기준인데 5분마다 체크 → 동일 신호로 하루에 여러 번 매수 가능

**수정 내용**:
- Redis에 봇별 마지막 신호 처리 날짜 기록
- 같은 날 이미 체크했으면 skip

```python
LAST_CHECK_KEY = "autostock:bot_last_check:{bot_id}"

def _already_checked_today(bot_id: int) -> bool:
    key = LAST_CHECK_KEY.format(bot_id=bot_id)
    val = _redis_client.get(key)
    today = date.today().isoformat()
    return val == today

def _mark_checked_today(bot_id: int):
    key = LAST_CHECK_KEY.format(bot_id=bot_id)
    _redis_client.set(key, date.today().isoformat(), ex=86400)
```

체크 타이밍 옵션 (bot 설정에 추가 검토):
- `signal_time: "open"` → 9:05 이후 첫 체크 시에만 실행
- `signal_time: "close"` → 15:20 이후 1회 실행 (기본값)

**완료 기준**: 동일 종목에 하루 2번 이상 매수 주문이 안 나감

### P5. ML 모델 — 피처 고도화
**파일**: `backend/tasks/ai_tasks.py`
**문제**: 모든 피처가 시점 스냅샷 → 추세 방향 정보 없음

**추가 피처 (8개 → 13개)**:
```python
# 변화율 피처
rsi_3d_delta     = rsi_t0 - rsi_t3          # RSI 3일 변화
macd_hist_slope  = macd_hist_t0 - macd_hist_t5  # MACD 방향
vol_ratio_5d     = vol_t0 / avg_vol_20d      # 거래량 급등 (이미 vol_map 있음)
price_vs_ma20    = (close - ma20) / ma20     # MA20 대비 위치 (%)
bb_squeeze       = (boll_upper - boll_lower) / boll_middle  # BB 수축 = 변동성 축소

# 이미 있는 것 유지 (8개)
# RSI, MACD_hist, Stoch_K, Stoch_D, ADX, MA20_MA50, ATR, Boll_pos
```

라벨 개선:
```python
# 현재: 5일 수익 > 1%
# 개선: 리스크 조정 수익 (5일 수익 / ATR 정규화)
atr_normalized_return = (future_price - close) / close / (atr / close)
train_y.append(1 if atr_normalized_return > 0.5 else 0)
```

Walk-forward validation 추가 (학습 품질 측정용):
- 전체 기간을 4분할, 마지막 25%는 OOS 검증
- OOS 정확도를 Redis에 저장 → LLM 프롬프트에 포함

**완료 기준**: OOS 정확도가 랜덤(50%) 대비 +5%p 이상
