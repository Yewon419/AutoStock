## 치명적 (실거래 전 반드시 수정)

### ① 백테스트 Look-Ahead Bias
- **파일**: `backend/services/backtest_engine.py:269`
- **문제**: 당일 종가로 지표 계산 → 같은 날 종가에 체결 처리. 실거래는 다음날 시가에만 살 수 있음.
- **영향**: 백테스트 수익률 15~30% 과장
- **수정**: `next_day_fill=True` 강제 적용, 당일 체결 옵션 제거

### ② 봇 사이클 중복 실행 방지 없음
- **파일**: `backend/tasks/bot_engine.py:83`
- **문제**: Celery Beat 5분 주기인데 사이클이 5분 초과 시 워커 2개가 같은 봇 동시 처리 → 중복 매수
- **영향**: 의도하지 않은 중복 주문
- **수정**: Redis 기반 봇별 lock 추가 (`bot_cycle_lock:{bot_id}`, TTL 6분)

## 심각 (소액 테스트 중에도 주의)

### ③ 포지션 사이징 버그
- **파일**: `backend/tasks/bot_engine.py:177`
- **문제**: `per_pos_budget = (cash + holdings_value) * position_size_pct / 100`
  보유 주식 평가액이 올라갈수록 다음 매수 예산도 커짐 → 레버리지 의도보다 커짐
- **수정**: 초기자금 기준으로 예산 계산하거나, 잔여현금 기준으로만 계산

### ④ 손절이 Redis 실시간가에만 의존
- **파일**: `backend/tasks/bot_engine.py:211`
- **문제**: Redis에 `rt:price:{ticker}` 없으면 전날 종가로 손절 판단. 장중 급락 시 당일 손절 미발동 가능
- **수정**: Redis 미존재 시 KIS 현재가 직접 조회 fallback

### ⑤ 트레일링 스탑 peak가 Redis에만 저장
- **파일**: `backend/tasks/scalping_engine.py:290`
- **문제**: Redis 재시작 시 peak 초기화 → 당일 최고가 기억 못함 → 트레일링 스탑 오작동
- **수정**: peak 가격을 Position 테이블에 컬럼 추가하여 DB에 저장

### ⑥ 주문 실패 시 재시도/상태 복구 없음
- **파일**: `backend/tasks/bot_engine.py:243`
- **문제**: KIS API 타임아웃 → 로그만 남기고 신호 버림. 실제 주문이 들어갔을 수 있어 브로커-DB 잔고 불일치
- **수정**: 주문 후 체결 확인 API 조회 + 재시도 로직 (최대 3회)

## 경미 (나중에)

### ⑦ 거래비용 구조 불일치
- **파일**: `backend/services/backtest_engine.py:281`
- **문제**: 백테스트 0.3% 고정. 실거래는 매수 0.015% + 매도 0.215%(증권거래세 포함)
- **수정**: 매수/매도 비용 분리 파라미터화

### ⑧ ML 모델 과적합 의심
- **파일**: `backend/tasks/ai_tasks.py:252`
- **문제**: OOS 정확도 55% = 랜덤(50%) 대비 +5%p. 검증 세트가 20개 샘플로 너무 작음. Accuracy만 사용 (클래스 불균형 미고려)
- **수정**: Walk-Forward 검증 구간 확대, Precision/Recall 추가

### ⑨ 생존자 편향
- **파일**: `backend/services/backtest_engine.py:230`
- **문제**: 상장폐지 종목 DB 없음 → 현재 살아있는 종목만 백테스트
- **수정**: 상장폐지 이력 데이터 수집 또는 경고 표시

### ⑩ 시장 휴일 체크 없음
- **파일**: `backend/tasks/bot_engine.py:107`
- **문제**: 설날/추석/임시휴장일에도 사이클 실행 → 주문 실패 로그만 쌓임
- **수정**: pykrx `get_market_trading_volume_by_date` 또는 휴장일 캘린더로 사전 차단

### ⑪ 봇 사이클 내 Race Condition (잔고/포지션 수 체크)
- **파일**: `backend/tasks/bot_engine.py:218,236`
- **문제**: `pos_count < max_pos` 체크 후 실제 주문 사이에 다른 워커가 끼어들면 max_positions 초과
- **수정**: DB 트랜잭션 격상 + SELECT FOR UPDATE
