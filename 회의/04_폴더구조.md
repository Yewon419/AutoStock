## Backend 구조

```
backend/
├── api/                  → 엔드포인트 (라우터)
│   ├── users.py
│   ├── market.py
│   ├── strategies.py
│   └── trading.py
│
├── services/             → 비즈니스 로직
│   ├── user_service.py
│   ├── market_service.py
│   ├── strategy_service.py
│   └── trading_service.py
│
├── models/               → DB 테이블 정의 (SQLAlchemy)
│   ├── user.py
│   ├── market.py
│   ├── strategy.py
│   └── trading.py
│
├── tasks/                → Celery 백그라운드 작업
│   ├── collect.py        → 주식 데이터 수집
│   └── indicators.py     → 기술적 지표 계산
│
├── broker/               → 매매 브로커 인터페이스
│   ├── base.py           → 추상 인터페이스 (ABC)
│   ├── kiwoom.py         → 키움증권 구현체
│   └── mock.py           → Mock 구현체
│
├── core/                 → 공통 모듈
│   ├── database.py       → DB 연결, 세션 관리
│   ├── config.py         → 환경변수, 설정값
│   ├── security.py       → JWT, Fernet 암호화
│   └── celery.py         → Celery 앱 설정
│
└── main.py               → FastAPI 앱 진입점
```

---

## 핵심 원칙

### 레이어 호출 규칙
```
api → services → models
(api에서 models 직접 접근 금지)
```

### 도메인 일관성
- api / services / models 모두 같은 도메인 기준으로 파일 분리
- "전략 관련 코드는 항상 strategies.py / strategy_service.py / strategy.py"

### core는 공통 전용
- 모든 도메인에서 공통으로 쓰는 것만 core에 위치
- DB 연결, 설정, 보안, Celery 앱

## 레이어 역할 요약

| 레이어 | 역할 | 비유 |
|--------|------|------|
| api/ | 요청 받고 응답 전달 | 홀 직원 |
| services/ | 비즈니스 로직 처리 | 주방장 |
| models/ | DB 테이블 정의 | 식재료 창고 |
| tasks/ | 백그라운드 작업 | 알바생 |
| broker/ | 키움/Mock 인터페이스 | 브로커 창구 |
| core/ | 공통 모듈 | 공용 도구함 |
